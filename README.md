# Kuros Manager

Personal productivity hub. Pulls from Slack and Outlook, summarizes via Claude, surfaces daily summaries, action items, risks, and person/team insights through a local web UI.

- **Architecture & rationale:** [PLAN.md](PLAN.md)
- **Implementation spec (source of truth):** [IMPLEMENTATION.md](IMPLEMENTATION.md)

## Quick start

Prereqs: Node ≥ 20.11, pnpm ≥ 9, Docker (or local Postgres 16), an Anthropic API key.

```bash
cp .env.example .env
# fill in ANTHROPIC_API_KEY at minimum
pnpm install
pnpm db:up           # starts postgres in docker
pnpm db:migrate      # creates schema and tables
pnpm dev             # runs backend (3000) and frontend (5173) in parallel
```

## Layout

- `apps/backend` — NestJS API + scheduler
- `apps/frontend` — React + MUI SPA
- `packages/shared` — shared TS types
- `data/` — gitignored runtime markdown store

## Summarizing missing days

Daily summaries are generated by the nightly job at 20:30, so days when the app wasn't running have synced data but no summary. On **Daily summary → Summarize missing days**, pick a look-back window (yesterday to 60 days). The preview lists every missing day and source, the number of items and a rough LLM call count, and nothing runs until you press Start. Jobs run oldest day first, can be cancelled, and stop after 3 failures in a row. New summaries flow into the knowledge base automatically. Weekly summaries have been removed; old weekly rows and files are left in place but no longer used.

## Knowledge base (LLM wiki)

Each user gets a personal wiki built with [Karpathy's LLM-wiki pattern](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f), stored as markdown at `data/users/<id>/wiki/`. You can open that folder in Obsidian too.

- **Raw sources** are the generated daily summaries, which are never modified. **The wiki** (`sources/`, `people/`, `teams/`, `projects/`, `topics/`, `daily/`, `answers/`) is written and maintained by the LLM. **`SCHEMA.md`** holds the conventions it follows; edit it to change how the wiki is kept.
- **Ingest:** every time a summary is saved, a background queue folds it into the wiki. One LLM call plans which pages to touch, and a second rewrites them. The queue then regenerates `index.md` and appends to `log.md`. While ingestion runs, a chip in the app bar shows live progress on every page (`Ingesting 12/40`). Click it for the ETA, the current item's phase (plan → write → save), what's up next, and recent results or errors. Backfill (last 14 days, or everything) is on **Knowledge → Wiki**.
- **Highlights** (`/knowledge`): a per-day dashboard synthesised from that day's ingested sources. It regenerates automatically about 3 minutes after a day's ingestion goes quiet.
- **Graph** (`/knowledge/graph`): an Obsidian-style force-directed graph of the wiki's `[[links]]`. Node size is link count. Hover to highlight neighbours, click to open a page. It has search, filters (sources, daily, answers, orphans, unresolved links) and force sliders. Every wiki page also shows a 1–2 hop **local graph**.
- **Ask** (`/knowledge/ask`): chat with the wiki. The LLM picks pages from the index plus a keyword search, then answers with `[[page]]` citations. *Save to wiki* files an answer under `answers/` so later questions can build on it.

Every wiki and chat LLM call uses the **deep** model from **Settings → AI**, through the configured provider (API key or Claude Code). Requires migration `1700000000006-KnowledgeBase` (`pnpm db:migrate`).
